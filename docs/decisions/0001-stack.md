# ADR-0001: нативное приложение и независимое ядро

Статус: принято для первого прототипа, 2026-10-18. Владелец выбрал оформление C / Ember / Sand.

Контекст: Windows 10/11 x64, real-time audio, один инженерный срез, минимум системных установок.

| Вариант | Выгоды | Цена |
|---|---|---|
| JUCE Components + C++20 | один стек GUI/audio, нативные компоненты, подходящая инфраструктура | AGPL/commercial licensing; дизайн нужно рисовать самостоятельно |
| Qt + отдельный audio backend | сильный GUI toolkit | больше зависимостей и интеграции аудио |
| Web UI + native bridge | быстрое прототипирование оформления | IPC, два lifecycle, дополнительный runtime |

Решение: предпочтительный стек из плана, JUCE 8.0.12 с SHA-256, core без JUCE.
Это намеренно закреплённая версия, не заявление о новейшей версии JUCE.
Следствие: обновления JUCE требуют отдельной проверки сборки, API и лицензии.
Оригинальный код пока не получает LICENSE; перед распространением выбрать совместимый путь.
Никаких плагинов и backend SDK в срезе 01; лишние модули JUCE не линкуются.

Windows-ресурсы компилируются CMake/MSVC из собственных .rc и manifest.
Причина проверена отдельно: juceaide rcfile успешно работает с относительными ASCII arguments,
но завершается с ошибкой при абсолютном пути с кириллицей в этой среде.
На Windows используется обычный CMake WIN32 target + JUCE_MODULES_ONLY, без сборки/запуска juceaide;
на других платформах juce_add_gui_app (там не проверялось).
Исходники JUCE не правились. PerMonitorV2 и UTF-8 объявлены в manifest; физический DPI ещё не проверен.
