# OpenDAW — подробное техническое задание для Codex

> Версия 0.1 · 18 октября 2026 · Рабочее название: OpenDAW
>
> Цель: создать бесплатную полноценную цифровую звуковую рабочую станцию (DAW) для Windows, по удобству и функциональности со временем сопоставимую с FL Studio, но с оригинальным кодом, архитектурой, визуальным языком и брендом. Первые 70 дней — рабочая, тестируемая основа, а не обещание полного паритета.

## 1. Твоя роль и принципы

Ты — Codex, ведущий инженер проекта. Выполняй задачи поэтапно, реализуй, собирай, тестируй и документируй результат. Пользователь — владелец продукта и принимает продуктовые решения. Не ограничивайся макетами и заглушками там, где требуется работающий звук. Перед крупными архитектурными изменениями предложи варианты и аргументы; не задавай вопросы по мелочам, выбирай разумные значения по умолчанию.

**Не заявляй о реализованной функции, пока она не проверена.** Если среда не позволяет запустить Windows GUI или аудиоустройство, честно укажи ограничение, проведи доступные автоматические тесты и дай короткий сценарий ручной проверки.

## 2. Продукт и пользовательские сценарии

Программа должна позволять:
1. Создать проект, выбрать BPM, размер такта, частоту дискретизации и аудиоустройство.
2. Добавить инструмент, создать паттерн в step sequencer или MIDI-ноты в piano roll.
3. Расположить паттерны и аудиоклипы в playlist, зациклить участок, использовать snap/grid.
4. Воспроизвести проект без щелчков, зависаний и заметных пропусков; остановить и перемотать.
5. Настроить громкость/панораму/посылы, применить эффекты и автоматизацию.
6. Сохранить, закрыть, открыть проект без потери данных; экспортировать WAV.
7. Со временем — использовать VST3-инструменты и эффекты, записывать MIDI/аудио, экспортировать другие форматы, поддерживать undo/redo, пресеты, шаблоны и сложную маршрутизацию.

Ориентиры качества: понятный workflow FL Studio, надёжность и гибкость профессиональной DAW, быстрый запуск, отзывчивый интерфейс, устойчивое сохранение. Не копируй пиксель-в-пиксель интерфейс, иконки, название, ресурсы, плагины или код FL Studio.

## 3. REA: исследование, а не копирование

**Репозиторий, который обязательно нужно изучить:** https://github.com/morluto/rea

Перед установкой:
- Прочитай README, LICENSE, требования, возможности, документацию и актуальные инструкции интеграции с Codex. Не предполагай, что команда установки или заявленная совместимость верна без проверки.
- Объясни пользователю, какие зависимости устанавливаются, какие внешние сервисы используются и какие разрешения потребуются. Не выполняй непроверенные скрипты с повышенными правами.
- Если REA полезен, предложи интеграцию и установи после разрешения пользователя, когда это затрагивает его систему.

**Разрешённый исследовательский процесс:**
- В первую очередь изучай публичную документацию JUCE, VST3 SDK и открытые DAW: https://github.com/LMMS/lmms, https://github.com/Ardour/ardour, https://github.com/zrythm/zrythm. Учитывай лицензии и условия повторного использования.
- REA можно применять к собственным бинарникам, разрешённым тестовым программам и приложениям с явным правом анализа; для FL Studio — только если конкретное исследование допустимо применимым правом и условиями использования.
- При изучении FL Studio отдавай предпочтение документации, пользовательскому поведению и самостоятельно сформулированным функциональным требованиям. Не извлекай, не переноси и не публикуй чужой исходный/декомпилированный код, ключи, DRM, закрытые ресурсы или проприетарные алгоритмы.
- Веди `docs/research.md`: цель исследования, источник, правовое основание, наблюдения на уровне поведения и самостоятельное инженерное решение. Если разрешение сомнительно — останови именно этот анализ и используй открытые альтернативы.

## 5. Техническая архитектура

**Предпочтительный стек:** C++20, CMake, JUCE (версию закрепить), Visual Studio 2022/совместимый MSVC, Windows 10/11 x64, GitHub Actions для CI. При выборе графического слоя сравни JUCE Components с альтернативами, но по умолчанию используй JUCE для GUI и аудиоинфраструктуры. VST3 — через законно используемый SDK/возможности JUCE.

Модули:
- `app/` — запуск, окна, настройки, команды, lifecycle.
- `core/` — ID сущностей, модель проекта, сериализация, валидация, undo/redo.
- `audio/` — device abstraction, transport, clock, граф обработки, буферы, рендер.
- `midi/` — события, тайминг, quantize, редактирование нот.
- `sequencer/` — паттерны, шаги, клипы, timeline, loop regions.
- `instruments/` — базовый sampler/synth; позже plugin host.
- `mixer/` — каналы, уровни, pan, sends, routing, metering.
- `effects/` — gain, filter, delay и другие собственные эффекты.
- `ui/` — playlist, piano roll, channel rack, mixer, browser, inspectors.
- `persistence/` — атомарное сохранение, версии формата, migration, recovery.
- `export/` — offline bounce WAV и проверка результата.
- `tests/` — unit, integration, audio rendering, serialization regression.
- `docs/` — архитектура, решения, лицензии, roadmap, исследование.

Правила аудиопотока:
- Никаких аллокаций, mutex, ожидания файловой системы, логирования в файл или блокирующих вызовов внутри real-time audio callback.
- Изменения UI передавай аудиопотоку через заранее подготовленные структуры/очереди и контролируемые snapshot-состояния; опиши владение памятью и синхронизацию.
- Все музыкальные события имеют устойчивые ID и точное время; заранее выбери модель PPQ/ticks и преобразование в sample positions.
- Раздели playback/render engine и UI; обеспечь детерминированный offline render там, где это возможно.
- Введи измерение CPU load, xruns/dropouts и профилирование горячих путей.

## 6. Формат проекта и устойчивость

Используй версионируемый формат проекта (например, JSON manifest + отдельные assets в папке или архиве), относительные пути к медиа, UUID для объектов, сохранение через временный файл с атомарной заменой, резервные копии и миграции. На первом этапе — без облачной синхронизации. Не сохраняй абсолютные локальные пути или секреты в публичный репозиторий. Тестируй round-trip сохранения/загрузки, отсутствующие файлы и повреждённый проект.

## 7. Качество и критерии приёмки

Минимальные автоматические проверки: сборка Debug/Release, unit-тесты для тайминга и моделей, round-trip проекта, WAV экспорт с известными сигналами, отсутствие клиппинга при типовых настройках, проверка транспортных операций, линтер/форматирование. Ручные тесты: звук через выбранное устройство, отсутствие щелчков на обычных сценариях, drag/drop нот и клипов, клавиатурные сокращения, HiDPI, resize, закрытие при несохранённых изменениях.

Не скрывай провалы тестов и не делай фиктивные коммиты. В каждом PR/дневном отчёте указывай: что реализовано, как проверено, что осталось, ограничения и следующий шаг.

## 8. Реалистичная цель 70 дней

**Обязательный MVP к дню 70 (при достаточном времени и успешных тестах):** Windows приложение, транспорт, базовый синтезатор или sampler, step sequencer, piano roll, playlist, простой mixer, сохранение/загрузка, экспорт WAV. VST3, запись аудио и сложная автоматизация — stretch goals, если базовая стабильность достигнута раньше. Полный функциональный паритет с FL Studio не входит в 70-дневный срок.

## 9. После MVP: дорожная карта к профессиональной DAW

**Этап A:** VST3 host, scanning/sandboxing policy, сохранение состояний плагинов, обработка ошибок и несовместимостей, latency compensation.

**Этап B:** запись аудио и MIDI, input monitoring, waveform cache, редактирование аудиоклипов, crossfades, time-stretch и pitch-shift.

**Этап C:** полноценная автоматизация параметров, sends/returns, sidechain, bus routing, multi-output instruments, PDC.

**Этап D:** встроенные инструменты и эффекты, preset browser, MIDI controllers, quantize/groove, comping, freeze/bounce, autosave/recovery.

**Этап E:** performance optimization, HiDPI/multimonitor, accessibility, масштабные проекты, установщик, crash reports с согласием пользователя, локализация.

## 13. Обязательные требования к визуальному дизайну и генерации изображений

**Внешний вид — приоритет продукта наравне с качеством звука.** Создать современную, оригинальную, эстетичную Windows DAW с единым профессиональным визуальным языком, а не стандартный интерфейс JUCE. Не копировать защищённые элементы оформления FL Studio.

### 13.1. Визуальная концепция
- Тёмная тема по умолчанию: гармоничные поверхности, сдержанные акцентные цвета, продуманные контрасты и понятная иерархия.
- Красивые Piano Roll, Playlist, Channel Rack, Mixer, Browser, транспорт, настройки и диалоги в единой дизайн-системе.
- Авторские иконки, удобные фейдеры, ручки параметров, контекстные меню, подсказки, плавные ненавязчивые анимации.
- Масштабируемость и корректная работа на Windows при 100/125/150/200% DPI; адаптация к изменению размера окна.
- Не жертвовать читабельностью и удобством ради красоты. Поддержать клавиатурную навигацию, видимый фокус и доступный контраст.
- Отделить тему и UI-компоненты от аудиодвижка. Не выполнять тяжёлую графическую работу в аудиопотоке.

### 13.2. Дизайн-система и контроль качества
Codex должен создать `docs/design-system.md` с палитрой, токенами цветов, сеткой отступов, типографикой, размерами, правилами иконок и состояниями элементов (hover, pressed, selected, disabled, focused). Создать `docs/ui-layout.md` с компоновкой главного окна и ключевых панелей. Для каждой UI-функции проверять реальную работоспособность, отсутствие наложений и обрезаний, корректную работу при масштабировании. При доступности GUI-тестирования сохранять скриншоты для визуального сравнения.

### 13.3. ChatGPT может генерировать изображения для проекта
**ChatGPT умеет самостоятельно создавать изображения по запросу пользователя.** Использовать эту возможность при разработке визуального направления: генерировать концепты главного окна DAW, Piano Roll, Mixer, Playlist, стартового экрана, логотипа, иллюстраций и других оригинальных ассетов. Начать с трёх различных визуальных концепций, выбрать понравившуюся, затем уточнять её и реализовать как настоящий интерактивный интерфейс.

Важно: у Codex нет гарантированного прямого доступа к генерации изображений ChatGPT. Если соответствующий инструмент недоступен в среде Codex, он должен подготовить подробные промпты, размеры, варианты и список ассетов в `docs/visual-asset-requests.md`; пользователь передаст запросы ChatGPT, получит изображения и добавит их в репозиторий. **Не утверждать, что изображения сгенерированы, пока это не произошло.** Для интерфейсных элементов предпочтительны масштабируемая векторная графика и отрисовка компонентами JUCE; концепт-картинки сами по себе не заменяют код интерфейса. Не добавлять чужие изображения без прав на распространение.
