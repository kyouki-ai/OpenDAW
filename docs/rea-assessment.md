# REA: оценка для OpenDAW

Дата проверки: 2026-10-18. Прочитаны официальный README, LICENSE, package.json,
installation.md, client-configuration.md, THIRD_PARTY_NOTICES.md и windows-ghidra-p0.md.
REA не устанавливался и не запускался. Совместимость с этой сессией не проверена.

По [README](https://github.com/morluto/rea) REA предоставляет MCP/CLI для исследования программ:
нативные бинарники через внешние analysis engines, JavaScript/Electron, .NET и другие форматы.
Анализ локальный; результаты получает агент, поэтому данные могут попасть его модельному провайдеру.
Это инструмент исследования, не аудиобиблиотека. Собственный код REA MIT, сторонние инструменты имеют свои условия.

[Установка](https://github.com/morluto/rea/blob/main/docs/installation.md) описывает
`npx rea-agents setup`: выбор клиента, просмотр изменений и подтверждение, затем перезапуск клиента.
Для Codex указан client ID `codex`. Возможен `setup --client codex --dry-run --json`.
Конфигурация MCP и workflow-инструкции меняются на уровне клиента; это не только зависимость проекта.
Main и опубликованный npm-пакет могут различаться — перед будущей установкой отдельно проверить версию registry.

Зависимости и разрешения при возможном подключении:

- Node/npm, загрузки из npm registry; текущий Node 24.19.0 удовлетворяет указанному в README порогу 24.11.
- Для нативного анализа нужен выбранный provider и его зависимости. Имеющийся JDK сам по себе не доказывает готовность Ghidra.
- Доступ к явно выбранным бинарникам, рабочим файлам анализа, запуск дочерних инструментов.
- Runtime/debugger workflows могут запускать процессы и менять состояние; нужна явная область исследования.
- MCP setup меняет пользовательские настройки и skill files; ничего из этого здесь не применялось.
- Hopper/IDA/JEB не приобретаются и не лицензируются автоматически лицензией REA.

[Windows Ghidra](https://github.com/morluto/rea/blob/main/docs/windows-ghidra-p0.md)
документирован как экспериментальный P0-путь. Нельзя обещать полную Windows-поддержку всех providers.
Это дополнительная причина не вводить инструмент в первую сборку DAW.

Инженерное решение: отложить подключение. Для native window, собственного synth и scheduler нужны
документация JUCE и тесты собственного кода. REA может пригодиться позднее для собственного OpenDAW.exe:
проверки символов, зависимостей, сравнений сборок или разрешённого тестового файла.
Не использовать его для извлечения кода/ресурсов FL Studio. Если появится конкретный сценарий,
сначала показать владельцу точную версию, пути изменений и внешние инструменты, затем согласовать установку.
