# Разработка

Перед изменениями читать исходный план, architecture.md, roadmap.md, daily-log.md.
Сначала небольшой законченный срез, потом проверка Debug/Release и обновление дневника.
Не ставить отметку «готово» без фактической проверки. Не добавлять зависимости без источника, версии и лицензии.

C++20, форматирование `.clang-format`. Сборки и тесты строго последовательно, `--parallel 1`, MSVC `/MP1`.
Форматировать только собственные `app`, `core`, `audio`, `ui`, `tests`; не трогать JUCE и build.
Новые ID создавать как UUID вне callback; перенос модели не должен менять идентичность.
В callback запрещены аллокации, mutex, файлы, сетевые запросы и уничтожение крупных состояний.
Не коммитить build, .tools, секреты, личные абсолютные пути, бинарники приложения.
Рекомендуемый первый коммит: `feat: bootstrap native OpenDAW studio shell and clock tests`.
Владелец разрешил обычные commit/push проверенных изменений в публичный kyouki-ai/OpenDAW;
см. AGENTS.md и docs/github-workflow.md. Релиз, публикация сайта и выбор лицензии — отдельные решения.
